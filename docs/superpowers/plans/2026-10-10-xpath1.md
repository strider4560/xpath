# XPath1 Implementation Plan

> For agentic workers: use subagent-driven-development for independent tasks, with parallel work restricted to separate owned files and fixed interfaces.

**Goal:** Deliver a reusable XPath 1.0 Rust crate tested against pinned Jaxen expectations.
**Architecture:** Immutable expression AST, generic tree navigation, fallible evaluator, optional owned XML adapter.
**Tech Stack:** Rust 1.85, std, optional roxmltree 0.20.
**Spec:** ../specs/2026-10-10-xpath1-design.md

## Global constraints

- No unsafe code; no mandatory dependencies; edition 2021; Rust 1.85.
- Preserve original oracle files and licenses; explicitly classify non-core cases.
- Stable node identity and document order, XPath-specific conversions and Unicode characters.
- No YANG-specific core semantics or implicit filesystem/network function access.

## Review focus

- Reverse axes and parenthesized predicates have different position semantics.
- Node-set inequality is existential rather than negated equality.
- NaN, infinity, signed zero and substring rounding must follow XPath 1.0.
- Namespace nodes have per-element identities and are not attributes or children.
- Malformed or deeply nested expressions must return errors without panicking.

## Tasks

1. Parser: own src/ast.rs and src/parser.rs. Write positive and rejection tests first, implement full grammar, source spans, namespace-aware QName lexical rules and recursion bounds. Verify with standalone rustc tests until the crate is assembled.
2. Core functions: own src/value.rs and src/functions.rs. Test conversions and all 27 core functions against XPath examples and Jaxen regressions, implement fallible node string conversions and correct comparisons supplied by evaluator.
3. XML adapter and corpus: own src/xml.rs, tests/jaxen.rs, tests/xml.rs and vendor provenance. Implement seven node types and a complete accounting harness over unmodified tests.xml. Keep extension cases explicit.
4. Integration: root owns src/lib.rs, src/model.rs, src/context.rs, src/error.rs and src/eval.rs. Test custom navigator, path focus, axes, operators, limits and errors. Integrate tasks 1–3, resolve all core corpus failures and write examples.
5. Review and release: independently review semantics and harness, fix concrete findings, run cargo test with all/default/no features, rustfmt, clippy, docs and package validation. Write README, conformance report and licenses, then archive and save the deliverable.

## Execution ledger

Ruling: proceed with design and implementation under the user's explicit request; approvals for routine reversible implementation are already authorized.
Ruling: a fresh isolated project directory is sufficient; there is no existing repository or worktree to protect.
Ruling: parser, value/functions and XML/harness files have disjoint ownership and documented interfaces, allowing independent work under the parallel-agents workflow.

Tasks 1–5: complete. Parser, core functions, XML/harness and root evaluator were
implemented with focused regression suites. Independent review findings R1–R3
were reproduced, fixed and verified; no review blockers remain. The final full
suite has 47 passing tests including all 296 Jaxen assertion definitions; the
dependency-free build has 35 passing tests. Formatting, clippy, documentation,
examples and Cargo package verification pass. See `docs/CONFORMANCE.md` for exact
evidence and limitations. The source is delivered as a local crate archive;
there is no upstream branch or remote repository to merge or publish.
